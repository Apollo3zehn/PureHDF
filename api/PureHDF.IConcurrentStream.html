Implemented by a class that can serve PureHDF's reads by absolute offset instead of through a stream cursor, and that is safe to read from concurrently.

public interface IConcurrentStream : IDisposable

Remarks

Implementing this interface has two effects.

First, it makes the source concurrency-capable. PureHDF isolates a cursor per read operation, so a dataset or attribute resolved once can be read from several threads through a single H5File. A cursor-based stream cannot participate in that - a second reader would share the one cursor - whereas every read declared here carries the offset it wants, so no cursor is involved at all.

Second, it tells the implementation which reads are worth caching. A range-request source typically wants to cache small structural reads aggressively - the same superblock, object header and B-tree bytes are re-read constantly - while streaming bulk payload straight through, since caching a multi-megabyte chunk that is decoded once only wastes memory. That is the whole reason there are two methods rather than one; both do the same thing to the buffer.

Both methods are required. Neither has a default implementation, deliberately: a source that silently fell back to a cursor-based read would reintroduce exactly the sharing problem this interface exists to remove.

THREAD SAFETY: both methods must be safe to call concurrently on the same instance, including with overlapping ranges. That is the point of the interface; PureHDF will issue concurrent calls whenever the caller reads concurrently.

An implementation that also inherits from Stream may still be passed to the Open(Stream, bool, H5ReadOptions?) overloads, but it is NOT automatically promoted to positionless mode there: it runs in cursor mode like any other Stream, and the concurrency this interface offers is not used. Pass it to the Open(IConcurrentStream, bool, H5ReadOptions?) overload to drive it positionlessly.

Parameters

offset long

The absolute offset, in bytes, from the start of the source's data - not relative to any cursor. Implementations must neither depend on nor mutate a cursor.

buffer Memory<byte>

The buffer to write the data into. It must be filled completely; a short read is an error and should throw (for example EndOfStreamException).

Returns

ValueTask

Remarks

This is the "actual data" signal: an implementation that caches may want to bypass its cache here, because bulk payload is usually large and read once. Must be safe to call concurrently.
